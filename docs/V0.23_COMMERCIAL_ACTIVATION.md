# GVibeDev.cc V0.23 — Commercial Activation Contract

## Purpose

V0.23 makes commercial, distribution and crowdfunding CTAs provider-aware without activating providers that do not yet have a real public endpoint.

No component should contain a copied PayPal, itch.io, Steam, Kickstarter or Patreon URL.

## Providers

Central commercial provider IDs:

- `paypal-support`
- `itch`
- `steam`
- `kickstarter`
- `patreon`

Provider resolution is handled by:

`src/config/commercial.ts`

The actual endpoint source remains:

`src/config/ecosystem.ts`

## PayPal

The public Support CTA remains disabled in V0.23.

The configuration supports two endpoint kinds:

- `donate-page` — preferred for the eventual dedicated GVibeDev support/donation page;
- `paypal-me` — available as an intentional fallback if GVibeDev chooses to use a PayPal.Me payment profile instead.

Required activation fields:

```ts
support: {
  provider: 'paypal',
  enabled: true,
  endpointKind: 'donate-page', // or 'paypal-me'
  url: 'REAL_PUBLIC_URL',
  qrAsset: null,
}
```

Do not activate the CTA until the public endpoint has been deliberately selected and tested.

`qrAsset` is prepared for a future site-owned QR image if GVibeDev decides to display one. It remains `null` in V0.23.

## Store / distribution providers

itch.io and Steam continue to use the centralized channel entries created before V0.23.

They become resolvable commercial endpoints only when:

1. a real product/store URL exists;
2. the channel `url` is set;
3. the channel is marked `visible: true`.

A project can then reference the provider instead of duplicating its URL.

Example:

```yaml
- type: wishlist
  provider: steam
  commercialAction: wishlist
```

If Steam is inactive, the CTA does not render.

## Crowdfunding providers

Kickstarter and Patreon use the same contract.

A project can be prepared for a provider without making it public. The CTA becomes active only when the central provider itself is active.

## Conversion event contract

Real commercial CTAs use:

- `data-analytics-event="conversion-cta"`
- `data-analytics-action="support|download|wishlist|buy|back|follow"`
- `data-analytics-provider="..."`
- project slug where the Product Hub already has project context

Analytics collection is still disabled in V0.23. These attributes only prepare future aggregate measurement.

## Principle

Commercial state belongs in project data.
Provider URLs belong in central configuration.
Components render the resulting state.

That separation allows a project to move through:

development → preview → download → wishlist → release → buy / support / crowdfunding

without hard-coding provider URLs across the site.
