# V0.20 — Shared Localized Shell Architecture

## What changed

Before V0.20, the English public site used Astro components while 18 Italian routes were stored as complete static HTML documents. Those Italian files duplicated:

- document `<head>`;
- header/navigation;
- language switch;
- footer;
- canonical / hreflang metadata;
- structured data;
- global shell behaviour.

That meant a global change could work in English while remaining stale in Italian.

V0.20 removes that duplicated shell.

## New structure

The converted Italian routes are now small `.astro` route wrappers.

Each wrapper loads one entry from:

`src/i18n/it-pages.json`

and renders it through:

`src/components/pages/LocalizedContentPage.astro`

which itself uses the same:

`src/layouts/BaseLayout.astro`

used by the English site.

As a result, both languages now receive the same:

- header;
- footer;
- EN / IT switch;
- canonical URL generation;
- hreflang / x-default;
- OpenGraph shell;
- structured data shell;
- analytics adapter;
- global accessibility plumbing.

`/it/support/` was already a native shared-Astro route and remains unchanged.

## What is intentionally preserved

V0.20 does not rewrite the validated Italian page bodies.

The translated body markup is centralized as content data and rendered inside the shared shell. Route-specific styles that were already validated are attached through the new named `head` slot in `BaseLayout`.

This is a compatibility bridge, not the final localization model.

## Why this is safer

A complete rewrite of 18 translated pages would mix two different operations:

1. removing duplicated shell infrastructure;
2. re-implementing every translated project layout.

V0.20 performs only the first operation.

That sharply reduces regression surface while solving the operational problem that motivated the milestone.

## Later migration

From V0.21 onward, product-specific shared bilingual components can replace localized content fragments one surface at a time.

Priority candidates:

1. Unum Sunt Sprite Studio distribution surface;
2. Arena Rubra Digital distribution / documentation surface;
3. project catalogue cards / CTA components;
4. About / Contact editorial bodies if further consolidation becomes useful.

The compatibility bridge can then shrink gradually instead of being removed in one risky rewrite.
