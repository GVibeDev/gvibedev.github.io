Unum Sunt Sprite Studio

Un workflow desktop che trasforma riferimenti di movimento in sprite puliti, allineati e pronti per l'esportazione.

Desktop Windows

Repository pubblico non ancora pubblicato. Nessun pacchetto release pubblico è ancora collegato.

Una pipeline al posto di una cartella piena di frame lasciati a metà

Unum Sunt Sprite Studio è un workflow desktop Windows costruito attorno a un problema di produzione ricorrente: convertire un riferimento di movimento in asset sprite non è un'unica operazione. Generazione, rimozione dello sfondo, selezione frame, pulizia, allineamento ed esportazione creano punti di errore differenti.

Lo strumento mantiene queste fasi visibili e ispezionabili invece di nasconderle dietro un unico pulsante “crea sprite”.

Lo stato pubblico attuale è Anteprima di sviluppo. È un'applicazione di sviluppo funzionante, ma repository pubblico e release impacchettata non sono ancora stati pubblicati.

Cosa copre il workflow attuale

Generazione con bridge WanGP locale

Il workspace Generate può inviare un'immagine di riferimento e un riferimento di movimento a un'installazione WanGP locale. Prompt, negative prompt, seed, risoluzione richiesta, numero di frame, FPS e step di generazione restano espliciti, mentre stato del job e output vengono tracciati dentro Sprite Studio.

WanGP è un'integrazione, non l'intera applicazione. Le altre fasi di produzione possono essere ragionate e testate indipendentemente dalla generazione.

Estrai e ispeziona la maschera

I frame del video sorgente possono essere analizzati rispetto a uno o più colori di sfondo. Il workspace di estrazione espone tolleranza, ammorbidimento dei bordi, pulizia e raffinamento strutturale della maschera invece di trattare la rimozione chroma come un effetto a singolo valore.

Viste separate per frame originale, maschera, risultato trasparente, sagoma rilevata e sfondo candidato rendono visibili gli errori prima che si propaghino.

Pulisci il risultato invece di accettarlo alla cieca

La pulizia automatica gestisce piccoli difetti alpha, mentre pixel painter e strumenti di selezione permettono correzioni locali. Selezioni rettangolari e lasso poligonale possono rimuovere aree indesiderate senza costringere l'utente a ridipingere un intero frame.

Allinea una sequenza attorno ad ancore utili

I frame di animazione raramente arrivano perfettamente registrati. Sprite Studio applica geometria di output, scala e modello di ancoraggio condivisi, poi consente correzioni per singolo frame. L'ispezione onion-skin aiuta a rivelare jitter facile da perdere osservando i frame singolarmente.

Seleziona meno frame, ma migliori

La fase di selezione intelligente analizza movimento, quasi-duplicati e anomalie in un intervallo. L'obiettivo non è semplicemente conservare ogni frame generato, ma proporre una sequenza compatta che corrisponda meglio al profilo di animazione desiderato.

Esporta asset per una pipeline di gioco

Export Studio può produrre immagini individuali o sprite sheet con layout, scala, formato immagine e sfondo controllati. Il prodotto finale è un pacchetto di asset, non soltanto un'anteprima dentro lo strumento.

Perché il setup è documentato pubblicamente

La generazione IA locale è la parte più incline a fallire per ragioni non direttamente legate a Sprite Studio. Durante lo sviluppo, un'apparente piccola incompatibilità di versione Python è bastata perché il bridge WanGP riportasse NOT READY.

È esattamente il tipo di dettaglio che GVibeDev deve esporre invece di nascondere. Un workflow utile assistito dall'IA comprende gestione delle dipendenze, ambienti riproducibili e diagnostica insieme allo strumento creativo visibile.

Assistito dall'IA, ma progettato attorno all'ispezione

L'IA viene usata dove aiuta — soprattutto nella fase opzionale di generazione — mentre le fasi successive restituiscono deliberatamente il controllo all'operatore. Le maschere possono essere ispezionate, i frame rifiutati, le ancore corrette e gli output ricostruiti.

L'obiettivo non è la massima automazione. È una catena di produzione in cui l'automazione fa risparmiare tempo senza rendere gli errori impossibili da vedere.

Setup / dipendenze

Sapere cosa serve allo strumento prima di installarlo.

Sprite Studio può essere usato come workflow di produzione, mentre la generazione IA locale aggiunge uno stack runtime WanGP separato. I due livelli sono documentati indipendentemente così che l'ambiente Python non venga nascosto dietro un generico pulsante “installa”.

Parte del setup locale WanGP validato. Le fasi di Sprite Studio diverse dalla generazione non dipendono dall'inferenza GPU WanGP.

Setup di sviluppo validato

Prepara e avvia lo stack WanGP locale validato

L'installer pubblico di Sprite Studio non è ancora disponibile, quindi questa guida si concentra sulla catena di dipendenze che ha causato più problemi: il runtime WanGP locale usato dal workspace Generate.

La versione di Python conta.

L'ambiente del bridge funzionante usa Python 3.11.14. Nei test precedenti, puntare il bridge a installazioni globali Python 3.13/3.14 più recenti produceva un risultato NOT READY anche se il resto dell'applicazione desktop poteva aprirsi. Mantieni WanGP isolato e seleziona dentro Sprite Studio il python.exe dedicato 3.11.14.

  1. Crea un ambiente Python 3.11.14 dedicato

    Mantieni WanGP indipendente dall'installazione Python globale. Il percorso sotto riproduce il layout di sviluppo noto come funzionante e può essere cambiato se mantieni la stessa separazione.

    conda create -p C:\AI\envs\WanGP python=3.11.14 -y
conda activate C:\AI\envs\WanGP
python --version

  2. Installa i pacchetti PyTorch / CUDA validati

    Questo fissa il set di pacchetti usato dall'ambiente Windows di generazione funzionante invece di lasciare a pip la risoluzione di uno stack arbitrario.

    python -m pip install torch==2.10.0 torchvision==0.25.0 torchaudio==2.10.0 --index-url https://download.pytorch.org/whl/cu130

  3. Installa i requirements WanGP e Triton per Windows

    Esegui questi comandi dalla root di WanGP Standalone, la stessa directory che contiene wgp.py e la cartella models.

    cd /d C:\AI\WanGP_Standalone
python -m pip install -r requirements.txt
python -m pip install triton-windows
python -m pip check

  4. Verifica CUDA prima di coinvolgere Sprite Studio

    Conferma che l'ambiente dedicato riesca realmente a vedere la GPU. Questo isola i problemi WanGP da quelli del bridge Sprite Studio.

    python -c "import torch; print(torch.__version__); print(torch.cuda.is_available()); print(torch.cuda.get_device_name(0) if torch.cuda.is_available() else 'NO CUDA')"

  5. Avvia WanGP una volta da solo

    L'avvio validato usava SDPA, profilo 4 e FP16. Un'esecuzione riuscita apre l'interfaccia WanGP locale, normalmente su 127.0.0.1:7860.

    cd /d C:\AI\WanGP_Standalone
C:\AI\envs\WanGP\python.exe wgp.py --attention sdpa --profile 4 --fp16 --open-browser

  6. Punta Sprite Studio al runtime WanGP dedicato

    In Generate, scegli Local WAN / WanGP Bridge. Imposta Python executable sul python.exe dedicato 3.11.14, wgp.py sul file dentro WanGP_Standalone, WanGP root sulla stessa cartella e seleziona il JSON delle impostazioni WanGP esportato usato dal preset. Valida il bridge prima di avviare un job di generazione.

  7. Mantieni intatto il contratto della working directory

    Il bridge deve essere eseguito con la root di WanGP Standalone come working directory. Usare un'altra cartella può rompere l'accesso a wgp.py, models/_settings.json e alle risorse relative WanGP anche quando il percorso Python è corretto.

Questa è la configurazione validata sulla macchina di sviluppo GVibeDev. Documenta un ambiente noto come funzionante, non afferma che WanGP possa funzionare soltanto con queste versioni esatte. Il comando finale di installazione/avvio di Sprite Studio verrà aggiunto quando saranno pubblicati il primo repository pubblico e la prima release.
