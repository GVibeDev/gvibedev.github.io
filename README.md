# G Vibe Dev — Portfolio / Project Hub

Baseline package: **GV-PORTFOLIO V0.1 — Foundation & Home Shell**

Repository target: `GVibeDev/gvibedev.github.io`  
Domain target: `https://gvibedev.cc`  
Hosting target: GitHub Pages  
Stack: Astro 7 + HTML/CSS, no frontend framework and no required backend.

## What V0.1 contains

- Astro static-site foundation.
- GitHub Pages deployment workflow.
- Brand-derived design tokens.
- Responsive sticky header and navigation.
- Accessible mobile navigation using native `<details>`.
- Hero using the supplied GVibeDev artwork.
- Featured project area.
- Web Apps, Tools, Worlds and BiggityKot homepage sections.
- Reusable project card system backed by an Astro content collection.
- Short manifesto block.
- GitHub block using the supplied retro-computer artwork.
- Footer.
- Favicons / web manifest / social preview asset.
- V0.1 scope and validation documents.

V0.1 deliberately does **not** create full project pages, download flows, embedded apps, analytics, a CMS or the final DNS configuration.

## Requirements

- Node.js `22.12.0` or newer.
- npm.

Astro is pinned to `7.1.6` in this baseline package.

## Local start

```bash
npm install
npm run dev
```

Then open the local URL printed by Astro.

Before the first GitHub Pages deployment, commit the `package-lock.json` generated by `npm install`.

## Production build

```bash
npm run build
npm run preview
```

The static build is written to `dist/`.

## GitHub Pages

1. Create or use the repository `GVibeDev/gvibedev.github.io`.
2. Copy this package into the repository root.
3. Run `npm install` and commit the generated `package-lock.json`.
4. Push to `main`.
5. In GitHub: **Settings → Pages → Source → GitHub Actions**.
6. Configure `gvibedev.cc` as the custom domain in GitHub Pages settings.
7. Configure the matching DNS records at Spaceship Domains.
8. Enable HTTPS when GitHub makes the option available.

The included workflow follows the current official Astro GitHub Pages deployment pattern.

## Content model

Project metadata lives in:

```text
src/data/projects/*.md
```

The schema is defined in:

```text
src/content.config.ts
```

Fields supported by V0.1:

- `title`
- `slug`
- `summary`
- `kind`
- `section`
- `owner`
- `featured`
- `sortOrder`
- `tags`
- optional `status`
- optional `cover` / `coverAlt`
- optional project `links` (`repositoryUrl`, `launchUrl`, `releaseUrl`)

No project status, version or completion percentage is shown unless it is explicitly supplied in project data.

## Real assets included

Original supplied assets are preserved under:

```text
src/assets/master/
```

Web-optimized derivatives used by the site live under:

```text
public/assets/
```

The master files are not referenced by the runtime.

## Copy status

The public-facing V0.1 copy is intentionally concise and currently English. It is structural copy, not a final editorial pass. Project-specific claims have been kept conservative where a full public project brief has not yet been supplied.
